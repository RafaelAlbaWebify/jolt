# Batch 18 — LinkedIn command center and market-preparation imports

**Baseline:** main 3caefe090dfe4b71ebd8eab16a2f2811ad6b5cd7. Two complete modules inspected at source level, covering queries, API-facing data models, transaction boundaries and file I/O. Risks are static; no live Windows or personal database evidence.

| Component | Findings |
|---|---|
| `backend/src/jolt/linkedin_command_center.py` | **LI-01 Medium:** `list_linkedin_command_center` fetches all captures and recommendations, then truncates response to 25/100; wasteful at scale. **LI-02 Medium:** `create_linkedin_capture` chooses previous capture by category only, potentially comparing unrelated target profiles and reporting misleading `changed_since_previous`. **LI-03 Medium:** connection export de-duplicates by URL or name+headline, preferring first entry in descending capture order; an incomplete latest observation can displace a fuller earlier one. **LI-04 High-consequence boundary to verify:** `_screenshot_path` derives a filesystem path from `Screenshot:` in stored notes and `build_linkedin_analysis_pack` reads bytes without a visible allowed-root constraint in this module. Trace who can write notes, authorization and evidence path policy; do not claim externally exploitable file disclosure without that trace. Import recommendations validates referenced capture IDs and commits once, a useful transaction boundary. |
| `backend/src/jolt/market_preparation_import.py` | **MP-01 High data-loss potential:** `_read_payload` treats malformed/unreadable existing JSON as empty state; a subsequent import may replace history with a new list. Test file corruption and write refusal; missing-file initialization is distinct from corrupt-file recovery. **MP-02 Medium:** module-local threading Lock and a predictable `.tmp` file are not process-safe across separate workers. Check deployment topology. **MP-03 Medium:** records retain last 25 imports, count lifetime imports, but unbounded raw_payload/action text can stress persistence and expose sensitive material; confirm validation, backups and export policy. Atomic `Path.replace` is a positive property but insufficient for interprocess coordination or recovering corrupted history. |

**Suggested regression checks:** existing history plus corrupt JSON must preserve file; two imports for same capture category but different URLs must not silently be treated as one target; screenshot evidence paths should be validated against an owned root; review SQL row limits and exact counts. No production changes authorized by this audit.
