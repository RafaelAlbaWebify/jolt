### Correctness priorities for change phase

1. **Never make archived application editable through alternate transition routes.** Confirm controller path and add negative regression before any change.
2. Do not lose structured outcome evidence when reopening; preserve historical analytics and human events.
3. Remove unsupported `Verified blocker` claims from heuristic language matching; verify actual requirements.
4. Invalidate/recompute readiness/evaluation when **evidence content** changes, not just engine/profile version.
5. Preserve explicit confirmation and recovery for permanent application deletion.
